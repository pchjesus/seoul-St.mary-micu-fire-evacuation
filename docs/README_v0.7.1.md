# MICU 화재대피 웹앱 v0.7.1

v0.7.0 FINAL을 보존하고 저장 안정화와 인원 관리를 추가한 검증 중인 개발본이다. 수정 이력(v0.7.2)과 서버·인증 기능은 포함하지 않는다. Android Chrome 에뮬레이터에서는 저장·새로고침·프로세스 재시작을 확인했다. 사용자 실기기와 iPhone 검증은 남아 있어 FINAL로 표기하지 않는다. 사용자의 최신 지시에 따라 지금은 배포하지 않는다.

## 실행

```sh
npm start
```

브라우저에서 http://127.0.0.1:8071 을 연다. 실행 시 npm 패키지를 설치할 필요는 없다. GitHub Pages에는 `index.html`, `style.css`, `storage.js`, `script.js`, `personnel.js`, `vendor/`를 같은 경로에 배포한다. XLSX는 로컬 vendor 파일을 사용한다. 이 버전은 웹 URL로 실행하는 정적 앱이며 `file://` 저장 동작을 보장하지 않는다.

## 저장 방식

- 기존 `fireEvacuationRosterDB_v0617` 데이터베이스를 버전 2로 업그레이드한다. 앱 버전을 올릴 때 저장소 이름을 바꾸지 않는다.
- IndexedDB `rosters`는 근무표 원본, `overrides`는 수동 배치, `personnel`은 인원 변경, `meta`는 활성 근무표·마이그레이션 표식·변경 번호를 저장한다.
- 저장은 트랜잭션 완료 후 별도 읽기에서 내용 일치를 검증한다. 완료 확인 전에는 성공을 표시하지 않는다. 실패하면 편집 내용을 유지하고 원인을 표시한다.
- 한 근무표의 인원·배치를 한 트랜잭션으로 저장한다. 삭제·동일 월 교체도 관련 데이터와 함께 원자적으로 처리한다.
- 다른 탭이 먼저 저장했다면 덮어쓰지 않고 충돌을 알린다. 입력을 복사한 뒤 새로고침해 최신 데이터를 불러온다.
- v0.7.0의 localStorage 미러는 최초 이전에만 사용한다. 기본 저장소에 데이터가 있으면 우선한다. 기존 미러를 변경하거나 삭제하지 않으며, 이후 빈 저장소에 예전 데이터를 부활시키지 않는다.
- 샘플 인원의 수정사항도 복원한다. 샘플과 같은 월의 실제 근무표는 저장 범위를 분리한다.
- 저장 데이터는 같은 브라우저·같은 사이트(origin)에만 있다. 다른 기기와 동기화하지 않는다. 사이트 데이터 삭제나 브라우저의 저장소 정리는 애플리케이션의 쓰기 검증만으로 막을 수 없다.

## 인원 관리

`인원 관리 · 추가 / 삭제`에서 이름·직종·선임 그룹을 입력한다. 변경사항 저장을 눌러야 확정된다.

- 추가·삭제: 현재 선택한 날짜·듀티에 적용한다. 원본 근무표 인원 삭제는 제외 목록에 기록하며 복원할 수 있다.
- 기존 인원 수정: 이름·직종·선임 그룹을 해당 근무표 전체에 적용한다.
- 이름 대신 원본 행 ID 또는 새 UUID로 사람을 구별한다. 동명이인을 허용한다.
- 간호사는 선임 그룹과 원본 행 순서로 배치한다. 추가 간호사는 같은 그룹의 원본 인원 다음 순서다. 사원·의사는 대피유도반에 배치한다.
- 배치된 인원 삭제는 확인 후 배정도 해제한다. 남은 인원은 기존 규칙으로 다시 배치한다.
- 배치 화면의 직접 이름 입력은 해당 날짜·듀티의 표시 이름 수정이다. 근무자 이름을 모든 날짜에서 바꾸려면 인원 관리를 이용한다.
- 근무표 교체·삭제 시 그 근무표의 인원 변경과 수동 배치도 초기화한다.
- 원본에 선택한 날짜 열이 없으면 인원은 `확인 불가`, 배치는 `근무 자료 없음`으로 표시한다. 해당 날짜의 편집과 앱 인쇄를 차단하며, 날짜 자료가 있는 실제 0명 상태와 구별한다.

## 파일 구성

- `storage.js`: 저장·이전·검증 경계. 추후 서버/API 구현으로 교체할 지점.
- `script.js`: 기존 Excel 파서, 배치 규칙, 화면과 저장 상태.
- `personnel.js`: 인원 관리 편집·저장 UI.
- `backups/fire_evacuation_prototype_v0.7.0_FINAL.zip`: 사용자 제공 안정판 전체 원본.
- Git 기준 커밋 `6dba564`: v0.7.0 FINAL. 개발 브랜치 `codex/v0.7.1-storage-personnel`.
- `TEST_REPORT.md`: 실제 수행한 검증, 증거, 미검증 항목.
- `CHANGELOG_v0.7.1.md`: v0.7.0 FINAL 대비 변경내역.
- `RELEASE_REPORT_v0.7.1.md`: 사용자용 변경·검증 보고서.
- `output/pdf/MICU_v0.7.1_Report.pdf`: 동일 보고서의 A4 PDF(4쪽).

## 검증

```sh
npm ci --ignore-scripts
npm test
npm run check
```

**자동검사 26개, 앞선 가상 근무표 PC 검사 48개를 통과했다.** 추가로 사용자 제공 Excel 2개에서 이름·근무코드 1,240개 값, 날짜·듀티 180건, 반 배치 540건을 대조하고 실제 브라우저 35개 항목을 최종 확인했다. 두 파일은 바이트 단위로 동일하고 10월 31일 자료는 없어 해당 날짜는 검증할 수 없다. 구체적인 환경·오류 주입 방식·미검증 범위는 TEST_REPORT.md에 기록했다.

저장 실패·복원·마이그레이션·동시 탭 충돌·재시도와 원본 대비 90개 날짜/듀티 결과, 파서, 인원 ID 및 배치 규칙을 검증한다. 가상 IndexedDB 테스트는 실제 모바일 브라우저 검증을 대신하지 않는다.

릴리스 순서: 안정판 백업 → 구현 → PC 확인 → 모바일 확인 → 회귀검사 → FINAL → 기존 GitHub Pages 주소에 배포. 운영 근무표는 배포 파일에 포함하지 않는다.
