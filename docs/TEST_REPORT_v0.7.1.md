### 측정 범위

- 확인창은 `window.confirm`의 수락/취소 반환값을 제어해 각 분기를 검사했다. 네이티브 확인창 클릭 검사는 아니다.
- `beforeunload`는 취소 가능한 이벤트를 발생시켜 경고 요청 여부를 확인했다. OS/브라우저의 실제 경고창 표시는 별도다.
- 오류/지연은 저장 API에 주입했다. 실제 디스크를 가득 채우거나 연결을 강제로 파괴하지 않았다. 트랜잭션 원자성/검증 불일치는 별도 자동검사로 확인했다.
- 브라우저 전체 프로세스 종료는 하지 않았다. 모든 **테스트 탭**을 닫고 새 탭에서 복원했다.
- PDF는 Chromium 출력 1페이지(612×792pt, Letter)다. 실제 프린터 및 A4 설정 출력은 하지 않았다.
- Windows Google Chrome/Edge는 검사하지 않았다. 이 절의 48개 검사는 가상 파일을 사용했고, 아래 별도 절에서 사용자 제공 파일 검증을 기록한다.
- 아래 Android 결과는 앞선 구현 시점의 검사다. 이번 PC 수정 후 모바일 전체 재검사는 하지 않았다.

## Android Chrome

로컬 Android 16 에뮬레이터 `emulator-5554`의 Chrome에서 네이티브 터치·스크롤·입력을 사용했다. 접속 주소는 호스트 루프백을 가리키는 `http://10.0.2.2:8071`이다.

1. 배치 수정에 `MobileSaveTest`를 입력했다.
2. 저장 성공 및 수정 모드 종료를 확인했다.
3. Chrome 메뉴의 **Refresh** 후 `한도MobileSaveTest윤` 표시를 확인했다.
4. Chrome 앱 프로세스를 종료하고 다시 실행했다. 같은 수정 이름이 복원됐다.
5. 인원 관리에서 `MobileAdded`를 추가하고 저장했다. 인원 수가 4명 → 5명이 됐다.
6. 해당 인원을 삭제할 때 네이티브 확인창에 배정 해제 안내가 나타났다. OK 후 저장하자 4명으로 복귀했다.
7. 추가·삭제 후 새로고침에서도 배치 수정값은 유지됐다.
8. 설명서 내부 터치 스크롤, 닫기, 고정 header/footer를 확인했다. 모바일 주소창이 보일 때 footer가 잘리던 부분은 동적 viewport 높이(dvh)로 보정했다.

실제 사용자가 문제를 겪은 휴대폰은 이번 세션에 연결되지 않아 동일 기기에서 원래 버그를 재현하지는 못했다. 에뮬레이터 성공을 실기기 전체 지원 완료로 간주하지 않는다.

## PC 재현 자료

`node scripts/pc-fixtures.cjs <출력폴더>`로 가상 XLSX/XLS를 생성할 수 있다. 운영 주소와 다른 포트에서 앱을 열고 위 표 순서로 검사한다. 기본 기준 날짜는 2026-09-24 E이며 생성된 9월 파일은 모두 E, 10/11월 파일은 D다. 자동 검사는 `npm test`, 문법 검사는 `npm run check`.

근무표 교체 회귀 재현: 두 탭에서 `2026-09-test.xlsx`를 사용 → B에서 `2026-09-replacement.xlsx`로 교체 → B의 5번째 배치 이름 수정·저장 → A의 ↻ 클릭 → 5번째 수정 이름 유지 확인.
