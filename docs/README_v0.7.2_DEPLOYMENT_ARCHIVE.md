# MICU 화재대피 웹앱 v0.7.2

**현재 상태: v0.7.2 RC (Release Candidate)**
현재 버전은 주요 기능과 테스트를 정리한 검토용 버전이며, 실제 기기/브라우저 검증이 남아 있어 FINAL로 확정하지 않는다.

v0.7.1 저장·인원 관리 기능을 유지하고 수정 이력을 추가한 로컬 검토본(RC)이다. 실제 휴대폰·iPhone 검증은 남아 있으므로 FINAL로 표기하지 않는다. 사용자 지시에 따라 배포하거나 외부 공유 서비스에 게시하지 않는다.

## 실행

```sh
npm start
```

브라우저에서 http://127.0.0.1:8071 을 연다. 프로그램 자체를 실행하는 데 외부 npm 패키지가 필요하지 않으며, 프로젝트에 포함된 정적 파일과 로컬 XLSX 라이브러리를 사용한다. 테스트를 실행할 때는 개발 의존성 설치가 필요하다. GitHub Pages에는 `index.html`, `style.css`, `storage.js`, `audit.js`, `audit-model.js`, `script.js`, `personnel.js`, `history.js`, `vendor/`를 같은 경로에 배포한다. XLSX는 로컬 vendor 파일을 사용한다. 이 버전은 웹 URL로 실행하는 정적 앱이며 `file://` 저장 동작을 보장하지 않는다.

## 저장 방식

- 기존 `fireEvacuationRosterDB_v0617` 데이터베이스를 버전 3으로 업그레이드한다. 앱 버전을 올릴 때 저장소 이름을 바꾸지 않는다.
- IndexedDB `rosters`는 근무표 원본, `overrides`는 수동 배치, `personnel`은 인원 변경, `meta`는 활성 근무표·마이그레이션 표식·변경 번호를 저장한다.
- 저장은 트랜잭션 완료 후 별도 읽기에서 내용 일치를 검증한다. 완료 확인 전에는 성공을 표시하지 않는다. 실패하면 편집 내용을 유지하고 원인을 표시한다.
- 한 근무표의 인원·배치를 한 트랜잭션으로 저장한다. 삭제·동일 월 교체도 관련 데이터와 함께 원자적으로 처리한다.
- 다른 탭이 먼저 저장했다면 덮어쓰지 않고 충돌을 알린다. 입력을 복사한 뒤 새로고침해 최신 데이터를 불러온다.
- v0.7.0의 localStorage 미러는 최초 이전에만 사용한다. 기본 저장소에 데이터가 있으면 우선한다. 기존 미러를 변경하거나 삭제하지 않으며, 이후 빈 저장소에 예전 데이터를 부활시키지 않는다.
- 샘플 인원의 수정사항도 복원한다. 샘플과 같은 월의 실제 근무표는 저장 범위를 분리한다.
- 저장 데이터는 같은 브라우저·같은 사이트(origin)에만 있다. 다른 기기와 동기화하지 않는다. 사이트 데이터 삭제나 브라우저의 저장소 정리는 애플리케이션의 쓰기 검증만으로 막을 수 없다.

## 수정 이력

저장 상태 옆의 **수정 이력**을 연다. v0.7.2 이후 저장된 변경을 최신순으로 확인하고, 시작일·종료일·작업·환경으로 필터한다. 날짜별 또는 환경별로 묶어서 볼 수 있다.

- 근무표 등록·교체·사용·삭제, 인원 추가·삭제·복원, 이름·역할 수정, 배치 변경·자동배치·수동 override, 초기화, 저장 성공·실패를 기록한다.
- 자동배치는 근무표를 명시적으로 사용하거나 저장한 인원·배치 변경으로 결과가 바뀔 때 기록한다. 단순 날짜 이동·메뉴 열기·저장 전 입력은 기록하지 않는다.
- 작업 시각(기록 당시 시차 포함), 변경 전후, 적용 범위, 결과, 앱 버전, PC/모바일/태블릿·OS·브라우저 종류를 보관한다. 브라우저 종류는 userAgent로 추정한다. 원본 userAgent·고유 기기 ID·IP를 로그에 저장하지 않는다.
- `현재 결과 내려받기`는 화면에 표시하지 않은 나머지 결과까지 **모든 필터 결과**를 내보낸다. `전체 이력 내려받기`는 필터를 무시하고 전체를 내보낸다. 이름은 Excel 수식으로 실행되지 않는 문자열 셀이다.
- 별도 `logs` 저장소는 근무표 삭제·교체 때 보존된다. 운영 저장과 이력 저장은 별도 트랜잭션이다. 이력 실패 때문에 검증된 운영 저장을 실패로 표시하지 않는다.
- 이력 쓰기 실패 시 현재 창의 대기 목록과 경고를 표시한다. 이력 화면 또는 경고의 `이력 저장 재시도`로 다시 저장한다. 같은 이벤트 ID는 중복으로 넣지 않는다. 읽기가 가능한 경우 대기 이력도 Excel에 `저장 대기 (현재 창)`으로 표시해 내보낸다.
- 대기 이력은 새로고침·종료 시 잃을 수 있다. 사이트 데이터 삭제 시 저장된 이력도 사라진다. 다른 기기와 공유하지 않는다. 운영 저장 직후 브라우저가 비정상 종료되면 이력이 남지 않을 수 있어, 중앙 감사로그나 복구용 백업으로 취급하지 않는다.
- 앱 파일 백업은 브라우저 데이터 백업이 아니다. DB v3으로 업그레이드한 사이트에서 DB v2 전용인 v0.7.1을 그대로 다시 실행하는 다운그레이드는 지원하지 않는다.

## 인원 관리

`인원 관리 · 추가 / 삭제`에서 이름·직종·선임 그룹을 입력한다. 변경사항 저장을 눌러야 확정된다.

- 추가·삭제: 현재 선택한 날짜·듀티에 적용한다. 원본 근무표 인원 삭제는 제외 목록에 기록하며 복원할 수 있다.
- 기존 인원 수정: 이름·직종·선임 그룹을 해당 근무표 전체에 적용한다.
- 이름 대신 원본 행 ID 또는 새 UUID로 사람을 구별한다. 동명이인을 허용한다.
- 간호사는 선임 그룹과 원본 행 순서로 배치한다. 추가 간호사는 같은 그룹의 원본 인원 다음 순서다. 사원·의사는 대피유도반에 배치한다.
- 배치된 인원 삭제는 확인 후 배정도 해제한다. 남은 인원은 기존 규칙으로 다시 배치한다.
- 배치 화면의 직접 이름 입력은 해당 날짜·듀티의 표시 이름 수정이다. 근무자 이름을 모든 날짜에서 바꾸려면 인원 관리를 이용한다.
- 근무표 교체·삭제 시 그 근무표의 인원 변경과 수동 배치도 초기화한다.
- 원본에 선택한 날짜 열이 없으면 인원은 `확인 불가`, 배치는 `근무 자료 없음`으로 표시한다. 해당 날짜의 편집과 앱 인쇄를 차단하며, 날짜 자료가 있는 실제 0명 상태와 구별한다.

## 파일 구성

- `storage.js`: IndexedDB 운영 데이터·로그 저장, 마이그레이션, 트랜잭션/다시 읽기 검증.
- `audit.js`: 공통 `logEvent()`, 저장 결과 기록, 환경 분류, 재시도, 필터·Excel 변환. 미래 API 연동은 내부 adapter를 교체한다.
- `audit-model.js`: 내부 사람 ID를 기준으로 저장 전후 모델의 차이를 기록으로 변환.
- `history.js`: 수정 이력 모달·필터·그룹·Excel 다운로드.
- `script.js`, `personnel.js`: 기존 파서·배치·인원 관리 및 저장 연결.
- - `CHANGELOG_v0.7.2.md`, `RELEASE_REPORT_v0.7.2.md`, `TEST_REPORT.md`: 변경내역, 사용자 보고서, 검증 범위.
- `docs/`: v0.7.1 README·검증 보고서의 보존본.

## 검증

```sh
npm ci --ignore-scripts
npm test
npm run check
python3 scripts/package-release.py
```

자동검사 39개와 PC Aside(Chromium 152, macOS) 검사 34개를 통과했다. Android 16 에뮬레이터 Chrome의 실제 조작 결과와 미검증 범위는 `TEST_REPORT.md`를 참조한다. 제공받은 9월·10월 Excel은 등록·사용·교체·삭제 검증에만 사용했으며 배포물에 넣지 않는다.

기존 자동검사는 저장 실패·복원·동시 탭 충돌·마이그레이션·원본 대비 90개 날짜/듀티·파서·인원 ID를 계속 검사한다. 추가 검사는 DB v2→v3 보존, 로그 수명, 성공/실패 분리, 중복 없는 재시도, 필터·그룹·Excel 125행 내보내기를 확인한다.

실행 시점의 테스트 근거는 버전별 보고서를 따른다. 이전 v0.7.1의 브라우저 검사 결과를 이번 버전에서 다시 수행했다고 합산하지 않는다.

## 현재 패키지 구조

```text
v0.7.2_RC/
├─ index.html
├─ style.css
├─ script.js
├─ personnel.js
├─ storage.js
├─ audit.js
├─ audit-model.js
├─ history.js
├─ vendor/
├─ tests/
├─ scripts/
├─ docs/
├─ README.md
├─ CHANGELOG_v0.7.2.md
├─ RELEASE_REPORT_v0.7.2.md
└─ TEST_REPORT.md
```

- `index.html`, `style.css`: 화면 구조와 디자인
- `script.js`: 기존 핵심 프로그램 로직
- `personnel.js`: 인원 관리
- `storage.js`: 브라우저 저장/복원
- `audit.js`, `audit-model.js`, `history.js`: 수정 이력 기록·변경 내용 계산·이력 화면
- `vendor/`: 로컬 XLSX 라이브러리
- `tests/`, `scripts/`: 개발 및 검증용 파일
- `docs/`: 이전 버전 문서 보존

위 구조는 현재 RC 패키지의 실제 구성 기준이며, 이전 버전 ZIP이나 별도의 `backups/`, `dist/` 작업 폴더는 이 패키지에 포함하지 않는다.
